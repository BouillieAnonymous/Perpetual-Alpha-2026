## 1. 本次讨论的出发点

目前的思路从宏观和产业逻辑出发：利率可能影响汇率，美元与黄金可能存在关联，地缘局势与石油供需可能影响原油，股指则包含更广泛的市场因素。

这些想法先作为假设保留。当前共同认识是：存在影响机制，不等于方向固定，也不等于能在我们的交易周期内获得成本后的收益。

影响可能发生在公告后的短时间，也可能通过预期和基本面在更长时间内体现；时间尺度需要单独验证。不能把“宏观”直接等同于“没有短期影响”，也不能把新闻后的涨跌都归因于该新闻。

## 2. 已记录的四条想法

### H01｜美联储政策与美元

**原始想法**：加息可能使美元走强，降息可能使美元走弱。

**待细化的问题**：

- 观察的是实际利率调整，还是相对于原有预期的变化？
- 对比哪一种货币？美元对欧元和对日元的变化能否采用相同判断？
- 关注公告后几分钟、几小时，还是数日？未来利率路径的信息如何处理？
- 如何区分政策消息、原有价格趋势与同时发生的其他事件？

**后续数据候选**：政策公告及首次发布时间、当时可获得的预期、相应汇率或合约价格、相关利率数据。

**先做的研究**：整理历史事件，比较不同预期变化下的后续收益和波动；拿不到可信的历史预期时，先研究公告窗口的风险变化，不用实际决议数值代替预期差。

### H02｜黄金、美元与对冲关系

**原始想法**：黄金与美元可能呈反向关系，具有某种对冲感觉。

**待细化的问题**：

- 关系在什么时间尺度上出现，是否随市场状态改变？
- 加入利率或风险状态后，美元是否仍提供额外信息？
- 同期一起变化，是否真的能预测之后的变化？
- 这个关系更适合辅助判断、调整仓位，还是构建双边持仓？

**后续数据候选**：黄金与美元价格、利率或实际收益率指标、波动指标，均需明确口径与更新时间。

**先做的研究**：先观察滚动关系，再检查“此前美元变化是否改善后续黄金判断”。同期相关不能直接当作领先信号；对冲效果也需要单独计算。

### H03｜原油、地缘局势与产业链

**原始想法**：中东局势、石油产业链相关事件可能引起油价波动，需要关注具体环节。

**待细化的问题**：

- 事件涉及生产、运输、库存还是需求？实际影响和可能影响怎样区分？
- 市场是否已经反映该风险？信息是否新增或超出预期？
- 能否用一致的标签或数值表达事件，而不是事后解释行情？
- 研究 Brent 的变化，还是使用了其他油种作为替代？替代关系需要怎样检查？

**后续数据候选**：Brent 或明确标注的替代行情、库存与供需报告、官方公告、带首次发布时间的新闻与事件标签。

**先做的研究**：先选一种重复出现、发布时间明确的事件，例如库存报告，检查前后波动与成本；复杂地缘新闻保留为后续研究，避免把所有事件都归为同一种方向信号。

### H04｜股指与市场总体趋势

**原始想法**：股指反映更广泛的市场趋势，影响因素复杂，难以精细化成量化系统。

**待细化的问题**：

- 是否可以先用指数自身的趋势和波动建立基准？
- 利率、汇率或少数相关市场的数据，是否提供额外信息？
- 是否需要成分股信息，还是聚合数据已足以支持当前假设？
- 对应外部市场休市时，数据是否过期？比赛合约和参考指数的变化如何区分？

**后续数据候选**：指数及对应比赛合约价格、相关利率与市场指标、交易日历；有明确研究问题后再增加行业或成分股信息。

**先做的研究**：采用少量可获得变量，与只使用价格和波动的基准比较；不以解释全部宏观与公司因素作为开始研究的前提。

## 3. 如何将想法逐步变为可执行判断

每条想法按以下顺序推进：

1. **选择一个小问题**：明确资产、条件和结果；一次不验证整个宏观叙事。
2. **定义时间范围**：分别研究事件窗口、小时级或日级关系，记录选取依据。
3. **确认数据可获得性**：明确来源、发布时间和接收时间；后来修订的数据不能冒充当时已知数据。
4. **建立对照**：与简单基准比较，允许结果否定原来的想法。
5. **检查实际价值**：计入成本、延迟、缺失和市场差异，验证未参与调参的数据。
6. **选择应用方式**：可以用于风险提示、暂停入场、调整仓位或提供方向信息；不要求所有想法最终都直接触发买卖。

记录阶段不锁定阈值、周期和买卖方向。进入实验时先写清规则再观察结果，避免看完行情后反复修改解释。

| 项目 | 需要填写的内容 |
|---|---|
| 编号与原始想法 | 保留提出时的判断及日期 |
| 具体假设 | 条件发生后，哪个资产在什么时间范围内可能怎样变化？ |
| 数据 | 来源、市场口径、时间范围、当时是否可获得 |
| 对照与方法 | 与什么基准比较，怎样划分开发和验证区间 |

| 实际价值 | 成本后表现、风险变化、数据与运行复杂度 |
| 状态与结论 | 待细化／待数据／实验中／放弃／继续验证 |

## 7. 策略筛选


按“资产与市场 → 研究问题 → 信号 → 方法 → 验证 → 执行”的顺序选择。领域可以是趋势、均值回归、跨资产或事件；机器学习是方法，不自动构成独立的交易理由。

筛选原则：

| 标准 | 实际检查 |
|---|---|
| 信息范围可管理 | 用少量可获取数据描述核心状态；不要求资产只受少数因素影响 |
| 信号可量化 | 当时能重复检测，规则与失效条件明确，避免事后解释 |
| 机会足够出现 | 统计新的有效机会、交易日期和成交量；不把重复采样算作独立机会 |
| 成本与执行可接受 | 完整周期成本后的收益空间、流动性、延迟与成交概率 |
| 数据与验证可行 | 历史和实时数据可获得，特征一致，支持时间外验证 |
| 组合风险可控 | 能放入统一预算，不因多资产或多信号重复扩大风险 |
| 团队能完成 | 开发、验证和维护量符合双方实际投入 |

候选资产先检查数据覆盖、报价完整度、价差、流动性和外部市场交易时段。候选策略再在相同成本和风险条件下比较，最后决定是否进入实时观察与小仓位验证。

收益、风险和算法解释性需要一起评价。满足参赛日期和成交额要求属于单独检查，不应绕过成本门槛或风险上限。[官方规则](https://perpetual-alpha26.github.io/about)

## 8. 实验与版本比较


验证顺序为：**历史回测 → 时间外验证 → 实时观察但不下单 → 小仓位测试网运行 → 正式版本选择**。

### 实验设计

- 按时间切分开发与验证数据；重叠的预测区间需要隔离，避免未来信息进入训练。标准化和特征选择也只使用训练区间。
- 从完整结束的 K 线生成信号，按之后可执行的价格模拟成交；不能看完收盘价再假设以同一价格无成本成交。
- 纳入手续费、价差、滑点和资金费；检查更差的成本和延迟假设下是否仍有可接受表现。
- 不把“价格碰到挂单”直接等同于成交。没有可靠挂单模型时，用更保守的执行假设。
- 一次只增加一个主要因素，固定对照数据与评估口径，保留失败实验。
- 短期正收益只能作为继续研究的证据，不能据此认定长期盈利能力。

可用时间序列验证工具支持按时间推进的切分，但仍需根据预测区间设计隔离规则。[TimeSeriesSplit 文档](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

### 统一比较指标

每次实验报告成本后净收益、每日收益波动、最大回撤、交易次数、累计成交额、费用、持仓时间、风险敞口以及异常情况；检查利润是否集中于极少数交易。

不要仅按预测准确率选模型，也不要把“交易少、波动低”自动认定为更好。需要同时考虑参与资格、收益和风险。空仓基准可用于研究比较，不代表满足参赛要求。

### R01｜Agentic Trading: When LLM Agents Meet Financial Markets

来源：[论文摘要与版本](https://arxiv.org/abs/2605.19337)、[v2 正文](https://arxiv.org/html/2605.19337v2)、[原 PDF](https://arxiv.org/pdf/2605.19337)。当前 v2 修订日期为 2026-10-04；v1 与 v2 的样本统计不同，本记录采用 v2。

**资料摘要**：这是一篇综述，不是一套直接可用的盈利策略。它用 Architecture–Capability–Adaptation 框架组织交易 Agent：感知、记忆、推理和执行；Alpha 发现、组合与风险管理；以及上下文学习、微调、RL、多 Agent 协作等适应方式。v2 汇集 185 项研究，其中闭环实证子集 80 项，并讨论时间切分、交易成本和执行可复现性。[v2 正文](https://arxiv.org/html/2605.19337v2)

**我们据此提出的路线，尚未验证**：

- 新闻 Agent：把带首次发布时间的信息转换成事件标签、影响资产、方向假设和有效期，再由规则或模型决定仓位。
- Alpha Miner：提出特征／因子与可检验假设，在隔离的研究环境生成代码、回测；通过验证后才人工纳入生产策略。
- 策略过滤 Agent：给已有趋势信号增加事件风险标记，先检验是否减少坏交易。
- RL：先研究是否适合仓位调整或执行选择；把方向预测、仓位分配和下单策略分开评估。
- 多 Agent：仅在单 Agent 有可测价值后再增加角色，记录增加的延迟、API 成本与决策冲突。

这些是我们的设计候选，不是论文证明的结论。Agent 不持有交易密钥，不运行任意生成代码到交易进程，不自动修改生产规则。其输出仍需符合 Decision 协议和独立风控。历史新闻、检索记忆及模型知识都可能泄漏未来信息；需要保存当时可用的数据快照，不能用今天的解释冒充过去的判断。

**最小实验**：同一价格基准，一组不用 Agent，另一组仅增加一种事件过滤；比较成本后收益、回撤、有效交易减少情况、延迟及 API 费用。没有稳定增益则保留普通基准。AlphaCrafter 仍只是之前提到的候选框架，不等同于这篇论文的实现，也未完成接入。

### R02｜zer0cache/hyperliquid-market-maker-bot

来源：[仓库 README](https://github.com/zer0cache/hyperliquid-market-maker-bot)、[算法说明](https://github.com/zer0cache/hyperliquid-market-maker-bot/blob/main/docs/ALGORITHM.md)。

**资料摘要**：Go 实现的双边做市项目，面向原生永续及 HIP-3 资产。README 描述 VWAP 锚定、分层报价、库存偏移、成交后不利价格变化监测和暂停／恢复机制。数据依赖 QuickNode，交易经 hyperliquidapi.com 路由并有 builder fee；示例资产为 xyz:CL。[README](https://github.com/zer0cache/hyperliquid-market-maker-bot)

**我们的判断与适配工作**：

- 可以借鉴公平价估计、库存越多越偏向退出、陈旧报价撤销、成交后 markout 记录等思想。

- 目前 30 秒 REST 采样不足以研究亚秒级做市。需要连续盘口、公开成交、自己订单／成交事件，以及队列与取消延迟记录。
- 看见价差并不等于赚到价差：可能只买到而卖不掉，或成交后价格继续逆向走。库存损失、费用及强制退出成本必须一起计算。
- 第一轮仅考虑单资产、单层双边报价的研究原型，先观察和模拟；多层、跨资产及复杂优化器另列后续实验。
- 当前 Decision 表达目标仓位，不能直接表达持续双边报价。做市需要单独设计 QuoteIntent／报价生命周期接口，经双方确认版本后接入，不能把它伪装成单一目标仓位。

**最小实验**：统计各时段实际价差、深度与成交活动；保守模拟挂单成交，记录成交后价格变化及库存。若没有可靠成交模型或净价差无法覆盖成本，就不进入自动做市。本轮候选状态从“非交付主线”调整为“值得评估，尚未选定”，不等于批准部署。

### S04 的具体边界

拟用买入偏离 = (参考价 − 卖一价) / 参考价；卖出偏离 = (买一价 − 参考价) / 参考价。先研究不同持仓时间下的后续可成交退出价格，再定阈值、最大持有时间与失效条件。这些公式只是检测特征，不保证回归。

参考行情需要币种、报价单位、合约口径和时间对齐；外部价格用于判断，不意味着我们能在外部市场同时成交，因此此路线不属于已锁定利润的双边套利。oracle 也可能包含所选外部市场的信息，不能把两者当作完全独立的证据。[官方参考价机制](https://perpetual-alpha26.github.io/docs/#asset-references-and-pricing)

### 成本门槛的统一语义

预期优势是基于历史条件分布的估计，而非已知未来收益。完整周期需扣开仓／平仓手续费、价差、滑点和资金费，再考虑估计误差与安全余量。信号分数不等于收益百分比，先验证两者关系。风险退出不受盈利门槛阻挡，不能因为平仓会亏钱而禁止退出。

官方当前基础未折扣费率为 taker 每边 0.09%、maker 每边 0.03%；实际以 fills 的 fee、feeToken 为准。例如双边 taker 往返手续费约 0.18%，尚未计价差等。未来资金费与持有时间未知，需要情景分析。[比赛费用](https://perpetual-alpha26.github.io/docs/#venue-mechanics)

## 12. 首轮比较方案与筛选标准

**讨论建议，不是最终团队决定**：保留一个趋势／动量基准，重点观察参考价偏离；做市先做数据可行性评估；Agent／RL 由队友并行研究，在相同评估口径下比较。

用户原来的筛选条件保留并细化：输入和逻辑可管理；事件出现足够频繁；信号容易量化。补充数据可得、净成本空间、组合风险和团队能完成。统计独立机会、交易日期、累计成交额，不能把反复采样同一事件当成新机会，也不能为凑资格绕过风控。

| 实验 | 基准与改变 | 交付物／淘汰依据 |
|---|---|---|
| E01 | 单周期趋势 → 少量多周期动量 | 时间外成本后对比；无稳健改善则保留简单版 |
| E02 | 固定仓位 → 波动缩仓／资金费过滤，逐项增加 | 可比风险下对照；不能把仓位变小导致回撤小单独视为成功 |
| E03 | 参考价偏离观察 | 偏离次数、持续时间、不同退出时间的净收益分布；实际可成交空间不足则放弃 |
| E04 | 做市数据可行性 | 数据连续性、净价差、保守成交及 markout／库存记录；无可信模拟不声称回测盈利 |
| E05 | 普通信号 → 一种 ML 或 Agent 过滤 | 相同时间段、成本和风险预算；同时计入 API 开支／延迟 |
| E06 | 固定仓位规则 → RL | 独立测试轨迹、奖励与成交模型；模拟偏差未解决则不接生产 |

每次实验先写参数与评价方式，再跑结果；保留失败实验与调参次数。外部长历史用于开发，par 实时／练习数据用于验证执行差异。现在采集了多久、质量如何需要查询数据库，不能因为服务已部署就认定数据足够训练。无足够未见样本时先报告探索结果，不做可靠优势结论。

### 15.2 外部参考价格的约束：保留为可测问题

官方区分 oracle、mark 与盘口成交价；oracle 来自外部源组合，mark 用于未实现盈亏、保证金和清算，资金费每小时发生。它们参与经济机制，并不保证盘口立刻回到外部价，也不保证某个退出时刻能按参考价成交。[官方指南](https://perpetual-alpha26.github.io/docs/#asset-references-and-pricing)

我们的补充研究：同时观察盘口对 oracle 的偏离、mark 对 oracle 的偏离，以及外部参考行情的新鲜度。统计偏离是如何结束的：盘口回归、参考价移动、还是两者一起变化；分别观察成交活跃／清淡时段。检查不同持仓时间内可执行的净收益和尾部损失。不能因为价格“应该回去”就持续加仓，也不能将“约束看起来不强”当成已经证实的市场事实。

### 15.3 各路线的收益来源对照

以下为我们的研究框架，不是已实现收益；完整净盈亏需结合成交、费用、资金费及未平仓的估值变化核对。

| 路线 | 试图赚什么 | 哪种情况容易失败 |
|---|---|---|
| 趋势／突破／动量 | 持仓期间价格继续沿信号方向移动 | 震荡、假突破、换仓过密 |
| 本地均值回归 | 偏离局部均值后恢复 | 所谓偏离实际是持续趋势 |
| 参考价偏离 | 比赛可成交价格与参考价的偏离缩小 | 偏离不恢复，或参考价向不利方向移动 |
| 配对／相对价值 | 两资产关系的残差缩小 | 对冲比例不合适，关系结构改变 |
| 跨资产领先滞后 | 一资产的信息预测另一资产后续变化 | 延迟后信息失效，相关仅是同步变化 |
| 做市 | 有利的双边成交价差 | 单边库存累积、不利成交、撤单不及时 |
| 资金费／carry | 持仓收到的净资金费 | 价格亏损、费率反转、进出成本超过收入 |
| 事件／新闻 | 新信息尚未充分反映后的价格变化 | 市场早已定价、时间戳错误、方向误判 |
| ML／Agent／RL | 改善上述信号、仓位或执行，间接增加净收益 | 过拟合、未来信息、模拟偏差、模型与调用成本 |

“对冲”和“波动缩仓”主要管理风险，本身不保证额外收入；“Agent”是一种实现方式，需明确其利用的收益来源。

### 15.4 S14：资金费收益研究卡

**通俗说明／官方事实**：资金费为正时，多头向空头支付；为负时，空头向多头支付。比赛每小时结算，其规模与持仓数量、oracle 价格及费率有关。实际账户资金费通过 userFunding 查询。[官方资金费说明](https://perpetual-alpha26.github.io/docs/#venue-mechanics)

**我们的候选**：观察某个资产在一段时间内的可收资金费，再考虑单边持仓或可验证的对冲。收钱的一边仍承担价格风险：空头收到资金费，但价格上涨造成的损失可能更大。费率变化与实际结算资格需依据当时规则和数据核对，不能把当前费率固定外推两周。

数据需求：fundingHistory、实时 funding／oracle、盘口、仓位、userFunding 和 fills。将收到的资金费、价格盈亏、手续费与执行损耗分开统计；跨资产对冲还要把两条腿的资金费都计算进去。不同资产的反向持仓不自动构成严格套利；现货对冲的资金与品种可用性尚未核实，不能套用比赛不存在的工具。

最小实验：首先只观察，不开仓。按预先设定的持有窗口计算资金费与可成交价格损益，比较单边与候选对冲版本。若净收益依赖极少数费率异常或不可实现的成交条件，放弃该版本。

### 15.5 S15：把“一个风险指数”细化成风险面板

用户提出给多空及事件风险做指标，帮助对冲。我们的建议是先分别展示几种风险，再决定是否汇总，避免一个数字掩盖问题。以下是待开发定义：

- **总敞口**：sum(abs(数量 × 价格))，表示多空仓位合计规模；对冲后它可能仍然很大。
- **净敞口**：sum(数量 × 价格)，只能作粗略方向参考。跨资产相加美元名义价值不表示市场风险相互抵消。
- **因子暴露**：用历史估计各资产对一个明确因子的敏感度，再组合有符号暴露；因子可以先选 BTC 收益，不假定黄金或外汇与它稳定关联。
- **组合波动**：用仓位权重与滚动收益协方差估算，但在突变时可能低估风险。
- **压力损失**：模拟 BTC／ETH 同跌、相关性改变、价差扩大、资金费反转等情景，检查可接受损失。
- **事件风险标签**：按事件种类、涉及资产和信息新鲜度记录，不把未经校准的 Agent 分数直接作为损失概率。

例如同时多 BTC、空 ETH，只有在选定的共同因子上、以估计的对冲比例配仓，才可能减少该因子风险；仍有相对价格风险、两边成本、保证金与执行风险。相关系数反映历史关系，不是固定对冲比例或未来保证。

最小实验：先对已有候选信号构造模拟组合，比较无对冲与有对冲版本在相同风险预算下的净收益、回撤、因子暴露与压力损失。先确定“要减少哪种风险”，再决定对冲资产和数量；最终交给统一账户风控限制总敞口、保证金及挂单风险。

### 16.2 五个方向的第一份研究交付

| 方向 | 第一份交付 | 进入下一阶段前要看到什么 |

| 趋势／动量 | 完整 K 线信号、固定入场退出规则和成本后对照 | 未参与调参区间仍有可接受表现；换手不过度 |

### 16.3 队友讨论用的一页策略卡

3. **动作**：什么时候入场、目标资产数量怎么计算、什么时候退出或改变方向。
4. **成本门槛**：预计持有多久，优势怎样估计，费用／滑点／资金费怎样计算。
5. **风险**：单资产及组合预算，是否对冲，对冲什么，以及强制退出条件。
6. **验证**：开发／验证区间、对照策略、调参次数、失败标准。

## 17. 10 月 11 日录音：Agent 自适应策略讨论

来源为用户提供的《新录音 2.m4a》。完整会议结论、投入约束、分工归属的不确定性及下一次讨论安排见[项目总览第 9 节](project-plan.zh-CN.md#9-10-月-11-日队友讨论录音纪要)。本节集中保存研究内容；下文明确区分录音中的想法与整理时提出的实验建议。此前聊天尚未取得的正文仍未补齐，本次录音是独立新增来源。

### 17.1 录音提出的研究方向

团队希望做 Agent，并让它根据市场状态和反馈改进策略。讨论中的“Agent”包含 LLM 调工具的工程概念，也包含用强化学习学习交易动作的想法；两者的职责尚未分清，不能直接把二者当作同一算法。

| 路线 | 录音中的想法 | 尚缺的定义 |
|---|---|---|
| 简单策略作 baseline | 复用已分享的开源做市策略，或从简单动量起步 | 最终选择、具体规则、比赛接口适配及成本后表现 |
| Agent 挖因子 | 让 Agent 寻找可供策略使用的信息／因子 | 因子输出格式、可用数据、独立验证及如何进入信号 |
| 固定框架内自适应 | 依据市场情况调整现有策略，讨论了微调与环境变化 | 调哪些参数、何时更新、可调整范围及失败时退回哪里 |
| 更完整的 Agent 决策 | 探索让 Agent 承担更广的策略选择和交易判断 | 可执行动作、反馈、评估、与执行端的边界 |
| RL 学习交易策略 | 从状态采取动作、获得奖励并更新策略 | 状态／动作／奖励、环境、训练数据、算法和验证方法 |

这些路线可以形成不同首版，也可以逐步组合；录音未决定全部同时实现。第 16 节的“趋势作基准、参考价偏离作重点候选”仍是此前整理建议，本次没有将它升级为共同决定，也没有最终决定采用做市。

### 17.2 需要保留的顾虑

**比赛市场与训练数据的差异。**讨论提出真实市场和比赛市场的价格／统计特征可能不同，也提到官方做市机器人。团队尚未确认其行为或价格拉回机制；不能假设比赛价格必定按某个速度回归外部价格。后续应把信号在外部历史数据上的表现与在比赛采集数据上的表现分别记录。

**做市遇到趋势或突变。**录音以平稳市场的双边挂单为例，担心暴涨暴跌突破原策略适用范围。Agent 识别市场并改变策略是一个候选解决思路，尚未证明能提前识别或减少损失。研究时仍需计入库存、未成交挂单、不利成交和撤单延迟。

**强化学习的训练方式。**讨论涉及离线／在线和 on-policy／off-policy，但没有作选择。离线历史回放能提供什么反馈、哪些订单无法从历史数据可靠模拟、更新是比赛前完成还是运行中发生，都需要单独定义。不能把几笔交易后的人工调参直接记录成已完成 RL。

**项目范围与开发时间。**团队同时有完整项目的愿望和比赛前尽快稳定框架的要求。更复杂模型是否有收益、额外模型费用是否必要、学习和实现所需工时，目前都没有确定结论。

### 17.3 将想法变成可交付方案：整理建议

以下是根据讨论提出的开发建议，**不是录音中已经通过的技术决定**。

1. **先冻结一个 baseline。**选做市或动量中的一个，记录资产、数据、规则、仓位、退出、费用及策略版本，让同一输入能够复现输出。
2. **一次只增加一种 Agent 能力。**先明确做因子研究、有限调参、策略选择或目标仓位决策中的哪一项；将“自我改进”细化成更新对象、触发条件、范围与版本记录。
3. **若选 RL，先写环境规格。**列出状态中可见的数据、动作及数量边界、奖励与费用计算、时间步、结束条件、训练／验证区间和成交假设，再选算法。先检验环境是否可信。
4. **用相同数据和执行假设作对照。**比较冻结 baseline 与加入 Agent 的版本，报告净收益、回撤、换手、库存／敞口和失败案例；未参与调参的数据单独验证。
5. **沿用现有接口。**数据需求用 DataRequest，市场和账户输入用 StrategyContext，交易输出用目标仓位 Decision，成交和拒绝反馈用 ExecutionReport；新增训练字段经双方对齐后再扩展协议。

闭环草案可写为“输入市场与账户状态 → baseline／Agent 产生目标仓位 → 执行端检查并执行 → 返回实际成交与账户反馈 → 研究端评估版本”。该闭环沿用现有三段结构，不表示自动训练、在线改代码或无人值守交易已实现。

### 17.4 周三讨论前的最小策略卡

框架草案应至少回答：选哪个 baseline；Agent 具体做什么；输入、输出和工具有哪些；反馈如何计算；在哪里训练／验证；首版何时能接入；哪些行为在首版不实现。若包含 RL，再补状态、动作、奖励和环境假设。

下一次讨论的产出应是一份范围明确、双方可以分别开发的方案。具体风险参数、模型、仓库复用范围和上线条件仍待决定；本次仅更新文档，未实施策略或发送交易。

## 19. 10 月 14 日：从 Agent 想法到可检验任务

### 19.1 本次方向如何演变

开头提出在因子研究中接 Agent；中段讨论冻结基础 LLM、改工具／提示／推理／harness；后段讨论让策略变成工具、让 Agent 处理信息，或者把方向判断整体交给 Agent。最后暂按 Agent 给出方向推进研究，但紧接着明确输出字段还要确认。因此，不把“已经选定传统动量”或“已经选定研究 Agent”记录成团队事实。

### 19.2 三个不同的优化对象

| 对象 | 本次对应讨论 | 可检查产出／待定义 |
|---|---|---|
| 收益策略 | 因子、方向、幅度／波动、动量等 | 资产、周期、收益假设、仓位、退出及完整成本 |
| Agent 系统 | 工具调用、提示、harness、候选筛选与反馈 | 固定输入下的输出、错误率、调用次数、耗时及收益增量 |
| 模型权重 | SFT、自训练、已有后训练模型 | 训练数据、算法和算力；首版暂不列为已确定实施方向 |

录音中多次使用“策略／模型／训练”，应先注明指的是哪一行。传统策略可以直接采用规则，不要求所有因子都先训练一个预测模型。固定基础 LLM 也可以优化 Agent 系统；系统改动仍需与收益表现分开记录。

### 19.3 Best-of-N 与多次采样：先定义评价

生成多个候选，再由 verifier 评分，或选择多次输出一致的答案，是录音中提出的推理改进候选，未选具体实现。建议先区分：格式／数值／约束的程序检查，和“哪项交易更好”的经济评价。前者可以当场检查；后者不能用决策时未知的未来收益作在线评分，也不能用同一验证数据反复挑选后再当作独立结果。

比较时固定数据、基础模型与版本、成本、风险预算和执行假设，记录调用预算与耗时。候选越多并不自动越好；多次结果一致也不构成市场预测正确的证据。保留单次调用及普通规则的对照。

### 19.4 两条最小验证路线：整理建议

**路线 A：实时方向 Agent。**给它当时可见的结构化行情与允许工具，输出具有资产、决策时间、有效期、预测／持有窗口、方向或明确不判断状态的信号，由确定性的仓位模块转换为目标数量；与简单规则 baseline 在相同账户预算和成本下比较。收益幅度、概率与波动不是首版强制的模型输出；若使用这些值，需要定义单位、窗口和验证／校准方法。

**路线 B：传统信号＋Agent 信息过滤。**固定底层策略，只增加一个事件或环境标签；与不用 Agent 及简单规则过滤比较，检验是否有成本后增益。它是与路线 A 对照的建议，没有取代录音末段的暂定方向。

离线因子研究 Agent 继续保留为后续候选，评价重点是有效假设发现与可复现研究；不要将它和实时交易 Agent、在线自训练同时作为首版交付。

## 20. 会后资料：模型替换与 Jev 判断模块候选

来源是用户补充的队友截图，不是录音。Fin-R1、DeepSeek V4.1 Flash 与暂对应 TypeSafe 的 Jev 的资料、身份边界和官方摘要统一见[学习资料第 11 节](agent-learning-resources.zh-CN.md#11-10-月-14-日会后新增deepseekfin-r1-与-jev)。这些是模型／模块候选，不是新确认的收益策略。

建议分开验证两件事：
