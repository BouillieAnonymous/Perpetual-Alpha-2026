# V1.1 修复记录

修改在本地解压目录进行，保留 V1 原包；没有重新扩展 Agent 架构。

## 已修复

- **N03 成组审批和成交**：单腿低于最小订单、数量取整为零、缺少报价、价差变化、数量不合步长或超限时，整组拒绝，不扣任何一腿的费用，也不提交部分账本。组内必须有非零反向目标，或两腿都明确归零。已有仓位满足目标的腿无需伪造成交。
- **配对生命周期**：配对仓位保存依赖资产；一腿到期、止损或止盈时联动退出，两腿不能因局部数据失败而单独平掉。已有组合的单腿再平衡也须携带另一腿的明确目标。
- **净额冲突**：其他策略把 N03 净额组合变成同向／缺腿时，整份 N03 贡献被抑制，原概率不重新分配。移除该贡献不会生成虚假的零目标去平无关旧持仓。
- **风控后的最终复核**：篮子被否决后重新计算保留仓位占用，不能让其他新增交易利用一笔实际上没有发生的减仓来突破总额度；否决会继续传递到其他依赖篮子，直到组合一致。
- **执行数量保持不变**：成交前直接检查已批准的绝对数量，不再做 `q × mid / mid` 后二次向零取整，避免浮点误差少一个数量步长。
- **真正的下一报价**：组内所有需要的 book event time 都前进后才模拟成交；不能把时间推后、报价没变化的旧快照当成新报价。
- **动态 Choice 候选**：只有当轮有合格信号／成本代理通过的策略进入请求，始终保留 NO_TRADE；响应键严格等于当轮选项。原始概率加权、Top-p=0.85 和不重分配尾部质量的设计保留。最后的数量／风险资格仍在概率权重确定后检查。
- **实际 Jev 客户端**：原 NotImplementedError 入口已替换为 TypeSafe 官方 HTTP 封装，Key 在本地 `.env.jev` 填写。固定模型、校验实际返回版本、完整分布、异常和超时、拒绝重定向、不自动重试；没有使用真实 Key 或发起真实请求。
- **可配置策略持有期**：支持 `[agent.strategy_horizon_minutes]`。收益情景窗口、风险尺度、历史 Funding 投影、探索机会时间桶和开仓到期时间跟随策略持有期；混合资产取实际贡献的最短周期。没有配置时继承统一 60 分钟，未捏造“已回测最优周期”。
- **标明收益代理**：Proposal 明确输出 `edge_model=heuristic-signal-proxy/1`、`edge_calibrated=false`；S14 明确历史 Funding 属性，模型问题也注明这些数值不是已校准的期望收益。
- **Windows 健康检查**：原 `paper_health.probe` 的 Windows `os.kill(pid, 0)` 替换为 OpenProcess(SYNCHRONIZE)／WaitForSingleObject 只读检查；子进程回归验证不会被探针发信号或杀死。POSIX 路径保留原语义。

## 这次没有以“修复”名义假定完成的事项

真实收益／概率校准、真实 PAS 历史回测、最优持有期、深度盘口因子、新闻源／情绪解析和真实账户保证金／跨市场订单恢复，需要数据或后续接入。当前仍是研究／Paper 执行；离线成组账本的原子性不代表交易所支持跨市场原子成交。Key 填入后可以调用 Jev，仍不会启动真实交易。

## 本地验证

Agent 概率、篮子、官方 HTTP 假响应和接口测试覆盖原 28 项及新增回归；完整测试结果保存于本目录 `validation-v1.1.json`。没有为了通过测试而改掉原始 PAS 固定统计样例的浮点末位差异。

官方接口核对：[Choice 请求与响应](https://docs.typesafe.ai/primitives/choice)、[固定模型版本](https://docs.typesafe.ai/models)。只使用真实返回的全分布；没有伪造 Jev 路由收益或准确率。
