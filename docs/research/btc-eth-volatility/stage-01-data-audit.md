### 4. 时间语义、字段与共同决策网格

UTC 网格为 **10-19 13:43 至 11-03 10:00，两个端点包含**，共 **21,378 个决策点 / 21,377 个候选一分钟收益区间**。首点在首次数据可得之前，保持 missing，不删掉它提高覆盖率。

| 时钟 / 字段 | 语义及本轮处理 |
|---|---|
| book.event_ms | 交易所返回的盘口时间；不是成交时间。有效性还要求与 payload.time 一致 |
| requested_ms | 本地请求开始；context 由 metadata/context 响应派生，其 requested 等于父响应 received，不能拿它当独立 Oracle 网络请求起点 |
| received_ms | 本地收到响应时间；不能让尚未接收的旧事件进入过去决策 |
| stored_ms | 事务内采样的存储时标，非精确 commit 时间 |
| available_ms | `max(requested, received, stored)`；本轮所有组件须 ≤ 决策 t；真实毫秒级数据库可见性仍 UNKNOWN |
| Bid / Ask / Mid | 从该资产最新有效 book 取一档价格，Mid=(Bid+Ask)/2；不拿 oracle/mark 填补失效盘口 |
| Oracle / Mark | 独立 context 最新 as-of 值；context.event_ms 通常为 NULL，上游生成时间 UNKNOWN；不从 context 推出同步性 |

### 5. 有效收益、连续性与 realized volatility

原管线收益为 `r_t = log(Mid_t) − log(Mid_(t−1))`。两端必须有效且相邻 UTC 网格、book.seq 不同、event_ms 严格前进。**只保留有数据的行后再 pct_change 会错误跨缺口，本轮没有这样做。**

本轮额外保守主口径在首次计算前固定：相邻 **Bid/Ask 顶层价格对完全不变**不产生新有效收益，且两 book 事件时间差必须在 **30–90 秒**。后者是名义 60 秒采样的固定容许带，不是搜索结果；同时保留原管线统计作为对照。即便通过此带，事件间隔也不精确等于 60 秒，所以只能称为“因果 UTC 分钟 as-of 收益”，不能称为精确事件时钟 1 分钟成交收益。

**关键限制：** 时间戳前进而价格不变可能是真实零收益，而非陈旧或重复上游数据；当前来源无法完全区分。本轮遵守不把重复报价当新有效收益的保守要求，将它们单列并在主口径切断收益链，**不把原管线含这些零收益的计数当最终有效数**。这会偏向活跃时段；不能直接拿保守筛选后的 RV 估计无条件 ETH 波动率。Bid/Ask 有变化而 Mid 恰好不变的零收益允许保留，BTC 51、ETH 98 个。

### 7. H1 的可用预测样本数量

固定 H1：在 t 使用 BTC 的 `RV15(t)` 评估 ETH 的未来 `RV30(t,t+30)` 是否有**增量**信息。仅有 X/Y 不是增量比较的充分设计；至少同时具备 ETH 自身 `RV15(t)`，另报告具备 ETH `RV60(t)` 的更长持续性基准。

特征只允许使用截至 t 的已可得价格；标签为 ETH t+1 至 t+30 的 30 个收益，必须到 t+30 之后才能知道。最后可标注的决策为不晚于 09:30 UTC。Stage 1 仅计完整窗口，没有查看 X/Y 回归关系、预测分数或择优结果。

30 分钟锚点按 UTC :00/:30 固定，不是观察缺口后贪心挑选最大不重叠集合。90 分钟锚点按 UTC 00:00、01:30、03:00…固定；最宽 60 分钟历史+30 分钟标签对应 90 分钟支持区间，相邻边界价格仍可共用，但收益区间不交叠。**25 或 14 只是预定锚点的合格块数，不是理论最大数，也不是“有效独立样本量”。** 波动率持续性、共同冲击及市场制度仍造成跨块依赖。

尤其不能把 2,335 行当作 2,335 次独立预测实验。保守规则还使目标窗口必须每分钟有新顶层价格，资格本身依赖未来活动状态；这不是特征泄漏，但构成 **label availability / selection bias**。仅在这些窗口评估可能夸大高活跃状态表现，不能推断无条件波动率关系。

### 8. Stage 2 固定时间窗口建议（未执行）

保持首次计算前记录的自然日划分，不根据 H1 结果或异常点移动边界。以下 UTC 区间均为 **[start, end)**，每一 split 内要求特征最早价格与标签末价都落在本 split 内，跨边界窗口全部剔除；因而与全段按日分配决策点的数量不同。

作为诊断对照，原管线 ETH过去15 的各 split 数量为 9743/325/110、5390/182/61、4184/138/46；该较大计数不能掩盖重复顶层价格口径问题。保守主口径在 **10-31、11-01** 的 H1 完整样本均为 0，末段全部有效决策集中在 11-02，样本状态覆盖尤其薄弱。不能为了得到更多有利结果，看到这个计数后把末段挪到更活跃日期。
