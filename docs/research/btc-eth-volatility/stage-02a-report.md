## 2. A、B 分别估计什么

### A. Pipeline as-of

两端报价必须在各自 UTC 决策时已可得、90秒 TTL 内、相邻分钟且 `seq` 不同、book event 严格前进。**新有效事件即使价格不变，也允许产生零收益**。复用同一事件、过期报价、缺失或异常仍无效；没有把旧报价重复使用产生的零值当成新收益。

其对象是“现有 PAS 顺序 REST 采样下，固定墙钟网格可观察的 Mid 波动”，包含真实价格不变/价格离散化时段。它更接近本地信息集上的日历时间波动率，但不是潜在有效价格或成交波动率：事件时间前进不能证明每次都是新的经济信息，源端刷新机制仍可能造成平滑；缺数据也可能非随机。A保留 Stage 1 原管线允许的事件跨度，不额外引入30–90秒限制；因此不是精确事件时钟60秒收益。

### B. Strict active-quote

在 A 之上，要求相邻 Bid/Ask 价格对改变且事件间隔30–90秒。任一收益不合格便使覆盖它的整个 RV 窗口缺失，不把15/30分钟改成“15/30次活跃更新”。Bid/Ask变化而Mid恰好不变的真实零收益仍保留。

其对象是“每分钟均有新顶层价格、事件时长合格的连续活跃墙钟窗口”。这不是对全部日历时间的稳健 RV 修正。它会系统性排除安静、价格离散化和陈旧来源难以区分的时段；若用于未来 Y，筛选还依赖**未来30分钟是否持续活跃**。这是事后标签可用性选择，而非决策时可实现的过滤。

**两口径权重相同，不因关系大小或正负选择其中之一。** A不是通过主观插补增加零收益，B也不是天然更接近“真实波动率”。源端静止报价与真实零经济收益的区分仍为 **UNKNOWN**。

### 同点比较揭示的关键事实

**VERIFIED：B 的2,335个完整 H1 时点全部属于 A；这些时点的 X、Z、Y 数值逐一完全相等，最大差为0。** 因此 A 在 B 时点上的相关、回归及分布与 B 完全相同。

原因是 RV 使用平方和，零收益对其数值贡献为0；B通过删掉不合格收益而删掉**整窗**，没有在共同完整窗内重估价格。同点完整窗不存在“A的零收益压低RV、B去零后抬高同一RV”的数值效应。这里全样本关系差异来自**保留哪些完整时间窗**（包括事件跨度筛选），不能归因为共同窗内不同的收益计算。反过来，B窗口外的价格不变时段是否真零仍不能仅凭此证明。

## 6. 重叠、依赖与共同冲击解释

**VERIFIED：** 每分钟完整H1行中，ETH未来RV在相差1分钟的现存配对上自相关A **0.9939** / B **0.9923**，相差30分钟为A **0.6412** / B **0.4510**。计算只匹配真实时间差，没有将缺口两侧压缩成相邻行。前者大量共享29个未来收益，不能用20,578或2,335行的普通IID回归标准误作推断。

30分钟锚点的标签收益区间不重叠，但相邻行的未来标签、历史特征可能使用同一段收益，且波动率有持续性。90分钟锚点使本H1的45分钟价格支持区间分离，并与Stage 1更宽60+30分钟口径兼容；仍不能保证跨块经济独立。没有将非重叠计数称作有效独立样本量。

**INFERRED：** X,Z相关约0.90，简单X,Y相关与ETH自身持续性相近、偏相关大幅变小，符合“共同波动状态或共同冲击”解释。也可能是BTC为未控制的ETH更长历史、非线性自身持续性或报价活跃状态提供代理信息；本阶段只控制ETH15，不能排除这些解释。

**UNKNOWN：** 共同oracle源、做市机制、宏观新闻或真实跨市场交易冲击各贡献多少，当前两资产REST Mid数据无法识别。两资产依次采样，虽然历史接收错位通常小于一秒，依然不是同步成交，不能从这些相关系数推出BTC因果驱动ETH。

Stage 1已标记10-30 01:32 UTC的ETH大幅变化；本轮未删除或缩尾。平方收益使大幅变化对RV及MSE权重更大；验证改善集中于部分日期可能与大波动状态有关，但本阶段没有通过删该异常或搜索冲击阈值建立新结果，不能断言某个事件是改善原因。

B未来窗口选择会主动排除平静/静止价格时段，末段10-31/11-01没有B完整H1样本，三天末段实际只剩一天。A/B共同时点三元组完全相等，已经验证**样本选择足以产生全段关系差异**；这不证明所有底层数据歧义已经消除。
